Manual QA checklist

Pending manual browser verification.

  • Phase 3: page hero keeps its height at 375 / 768 / 1440 and the breadcrumb wraps without overflow.
  • Phase 3: form fields show red only after a submit attempt; select chevron and custom checkbox/radio render in Safari, Chrome, Firefox.
  • Phase 3: filter chips hide non-matching cards and reveal the empty state; "All" restores.
  • Phase 3: slider arrows disable at both ends; hidden below 768px; track swipes on touch.
  • Phase 3: lightbox opens from the detail split, Esc / backdrop close, arrow keys and swipe step, focus returns to the thumbnail.
  • Phase 3: every new transition is neutralised under prefers-reduced-motion.
  • Desktop and mobile layout matches current geometry.
  • Mobile menu opens, closes, and supports keyboard focus.
  • Booking rejects missing or reversed dates.
  • Guest menu selection updates visible value.
  • Room tabs and detail toggle update content.
  • Amenities arrows scroll track; taller cards (tagline + hours) stay equal height.
  • Footer social links (Instagram, Facebook, LinkedIn, TripAdvisor) open in a new tab.
  • FAQ filters and accordion preserve accessible state.
  • Images load from local output/images paths.
  • Focus-visible styles remain visible on every control.
  • home.html: every Book Now (data-booking-cta) and the hero booking widget open the STAAH URL in a new tab; widget passes checkin/checkout/guests.
  • All buttons render as pills in every variant (primary, outline, gold, light, ghost).
  • home.html: language switcher links resolve once the /id/ mirror exists.
  • home.html: room panel Book Now uses body[data-booking-url] (STAAH); index.html keeps Booking.com.
  • home.html: gallery mosaic keeps captions readable on touch devices.
  • home.html: WhatsApp float does not cover the footer language switcher on 375px.
  • Empty-state blocks render correctly once hidden is removed.
